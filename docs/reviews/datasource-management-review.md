# 数据源管理前后端 Review

## 已修复问题

1. **连接密钥泄漏**：详情接口原样返回 `originalJson`，可能包含密码、Token 等敏感字段；连接地址也可能通过 URL 参数或 userinfo 暴露凭据。
2. **编辑密码被覆盖**：编辑页面无法安全回显密码，提交空值或掩码时可能覆盖已保存密钥；编辑态连接测试也存在同样问题。
3. **接口缺少权限保护**：数据源 CRUD、连接测试、Catalog 预览和插件配置接口未统一进行后端权限校验。
4. **安全异常被吞并**：数据源模块通用异常处理器可能把鉴权异常转换成普通业务失败响应。
5. **分页和统计失真**：前端只加载后端第一页，再在当前页进行搜索、状态过滤和统计，导致后续数据不可见且总览数量错误。
6. **前后端状态值不一致**：前端仍按旧状态值渲染，后端返回的 `CONNECTED`、`DISCONNECTED`、`UNKNOWN` 无法正确展示。
7. **动态表单协议不一致**：插件配置和安装接口成功码按 `0` 判断，而 Yak Ops 业务接口成功码为 `200`；Switch 字段绑定和正则、最小值、最大值规则也未生效。
8. **SQL 预览安全边界不足**：Catalog 预览、字段解析和统计可接收任意 SQL。
9. **重复提交**：创建、编辑和连接测试按钮缺少请求中状态，连续点击会重复发送请求。
10. **请求协议问题**：连接测试使用 GET 触发有副作用操作，查询参数也未统一 URL 编码。

## 当前策略

- 列表接口不返回原始连接 JSON；详情接口仅返回递归脱敏后的配置。
- 编辑或测试已有数据源时，掩码、空值和缺失敏感字段沿用数据库中的原值。
- 页面读取权限使用 `resource:data-source:read`，写操作继续复用已有 `datasource:create/update/delete/test` 权限。
- 搜索、状态筛选、分页和总览统计全部由后端完成。
- SQL 模式的 Catalog 字段解析、预览和统计仅接受单条 `SELECT`。
- 保留已保存连接测试的 GET 路由以兼容旧调用方，前端统一改用 POST。

## 仍需后续规划

数据库中的连接参数当前仍为明文持久化。本次修复重点是避免 API 和前端泄漏，并安全处理编辑回显；如需实现静态加密，应在明确密钥托管、轮换和历史数据迁移方案后单独实施。
